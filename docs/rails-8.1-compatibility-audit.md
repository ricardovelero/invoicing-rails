# Rails 8.1.3.1 compatibility audit

Date: 2026-09-16. Scope: Rails 8.0.5.1 → 8.1.3.1, keeping Ruby `~> 3.3`, `config.load_defaults 8.0`, existing gem versions where possible, and Tailwind CSS v3.

## Conclusion and evidence

The framework source audit found no required configuration rewrite or reason to adopt Rails 8.1 defaults. Runtime validation subsequently found a Carmen country-name lookup deprecation missed by the initial static gem coverage. This third-party compatibility issue requires a localized remedy; no compatible Carmen release exists. Keep the framework and dependency change small and validate existing behavior. The accompanying [upgrade record](rails-8.1-upgrade.md) contains baseline and post-upgrade command results and the chosen remedy.

Context7 was consulted first: `resolve_library_id` for Ruby on Rails, then `query_docs` against `/rails/rails/v8.1.2`, its latest offered source version. Because that index does not cover the exact requested patch, the audit subsequently inspected the official `v8.1.3.1` release source archive, gemspecs, changelogs, configuration implementation, and application generator templates. Framework gemspecs were compared with the locally installed 8.0.5.1 gemspecs. Official upgrade guidance recommends testing the existing application before updating and distinguishes framework upgrades from adopting new defaults. [Upgrade guide](https://guides.rubyonrails.org/upgrading_ruby_on_rails.html#general-advice), [exact target source](https://github.com/rails/rails/tree/v8.1.3.1).

## Mandatory dependency changes

| Change | Requirement and reason |
| --- | --- |
| Rails and its 12 component gems | Rails 8.1.3.1 requires every framework component at the same exact version. Includes Action Cable, Mailbox, Mailer, Pack, Text, View, Active Job, Model, Record, Storage, Support, and Railties. |
| Add `action_text-trix` | Action Text 8.1 adds the dependency `~> 2.1.15`, even though the application does not use rich text. This is required by the framework metagem. |
| Preserve existing `json` | Active Support 8.1 adds an unconstrained runtime dependency on `json`. The baseline already locks `json` 2.7.1, which satisfies it. |
| Remove `benchmark` 0.5.0 from the lockfile | Active Support removes its direct dependency on `benchmark`. The reviewed resolution confirms no remaining dependency requires it, so Bundler drops the obsolete entry. |

The reviewed resolution adds `action_text-trix` 2.1.19 and preserves all unrelated gem versions. No other external runtime dependency requirement changed across the 13 Rails gemspecs. The target requires Ruby ≥ 3.2.0, so the existing Ruby 3.3 runtime is supported. Rails requires Bundler ≥ 1.15.0; the upgrade does not require changing the application's Bundler version. [Rails gemspec](https://github.com/rails/rails/blob/v8.1.3.1/rails.gemspec), [Action Text gemspec](https://github.com/rails/rails/blob/v8.1.3.1/actiontext/actiontext.gemspec), [Active Support target gemspec](https://github.com/rails/rails/blob/v8.1.3.1/activesupport/activesupport.gemspec), [Active Support baseline gemspec](https://github.com/rails/rails/blob/v8.0.5.1/activesupport/activesupport.gemspec).

## Application API audit

The application uses PostgreSQL, ordinary Active Record models with primary keys, nested invoice line items, locking and transactions for invoice numbering, strong parameters, Devise authentication, Pagy pagination, `pg_search` scopes, Turbo responses, Sprockets, import maps, and the existing Tailwind v3 build. Configuration enables local disk Active Storage and the standard Action Cable framework, without application attachment declarations or concrete subscription channels. Only the empty `ApplicationJob` base class exists; no concrete jobs, custom job serializers, or explicit queue adapter were found.

## Framework defaults intentionally deferred

Keeping `config.load_defaults 8.0` excludes all seven settings introduced by the target's `load_defaults "8.1"` branch. Previous behavior remains:

| Setting | Retained 8.0 behavior | Deferred 8.1 behavior |
| --- | --- | --- |
| `action_controller.escape_json_responses` | `true` | `false` |
| `active_support.escape_js_separators_in_json` | `true` | `false` |
| `action_controller.action_on_path_relative_redirect` | `:log` | `:raise` |
| `active_record.raise_on_missing_required_finder_order_columns` | `false` | `true` |
| `action_view.render_tracker` | Regex/ERB tracker (effective behavior with unset config) | `:ruby` |
| `action_view.remove_hidden_field_autocomplete` | `false` | `true` |
| `yjit` | `true` through loaded 7.2 defaults | Disabled in development/test; enabled elsewhere |

Do not add explicit old-default overrides or enable the generated defaults initializer. The old `to_time` setting is no longer loaded by the framework; its behavior is retained automatically. Signed-ID legacy mode is preserved separately, not introduced by `load_defaults 8.1`. [Target defaults implementation](https://github.com/rails/rails/blob/v8.1.3.1/railties/lib/rails/application/configuration.rb#L344), [defaults initializer template](https://github.com/rails/rails/blob/v8.1.3.1/railties/lib/rails/generators/rails/app/templates/config/initializers/new_framework_defaults_8_1.rb.tt), [Action View defaults](https://github.com/rails/rails/blob/v8.1.3.1/actionview/lib/action_view.rb#L94).

The JSON-renderer implementation deprecates explicitly setting `escape_json_responses = true`. The app does not set it; retaining the inherited old value does not itself call that deprecated setter. Active Support's separate `escape_html_entities_in_json` remains `true`; the 8.1 defaults branch changes only its JavaScript-separator escaping setting. Any future observed warning must be traced rather than silenced. [JSON renderer](https://github.com/rails/rails/blob/v8.1.3.1/actionpack/lib/action_controller/metal/renderers.rb#L31), [JSON encoding defaults](https://github.com/rails/rails/blob/v8.1.3.1/activesupport/lib/active_support/json/encoding.rb).

## Generated configuration review

Direct comparison of the 8.0.5.1 and 8.1.3.1 generator templates found no required edits to application, test-environment, database, or cable templates. Existing application configuration is more specific than generated defaults and must be retained.

- Development adds verbose redirect logging and quiet asset logging. Quiet assets are already configured; redirect logging is optional and changes logging behavior. Reject generated churn.
- Production generator changes SSL handling for new Kamal applications. This app runs behind Render's SSL termination and explicitly sets `assume_ssl`/`force_ssl`; preserve those settings, credentials, Postmark delivery, host, asset behavior, and logging.
- Puma template differences are comments. Preserve existing server configuration.
- Storage template removes commented Azure examples. No active Azure service exists; comment removal is unnecessary.
- The new defaults initializer contains deferred settings and is unnecessary for this framework-only upgrade.
- Rails 8.1 alphabetizes schema columns during dumps. Restore incidental schema reordering rather than commit generated churn; no migration is required.

[Development template](https://github.com/rails/rails/blob/v8.1.3.1/railties/lib/rails/generators/rails/app/templates/config/environments/development.rb.tt), [production template](https://github.com/rails/rails/blob/v8.1.3.1/railties/lib/rails/generators/rails/app/templates/config/environments/production.rb.tt), [Puma template](https://github.com/rails/rails/blob/v8.1.3.1/railties/lib/rails/generators/rails/app/templates/config/puma.rb.tt), [storage template](https://github.com/rails/rails/blob/v8.1.3.1/railties/lib/rails/generators/rails/app/templates/config/storage.yml.tt), [schema upgrade guidance](https://guides.rubyonrails.org/upgrading_ruby_on_rails.html#upgrading-from-rails-8-0-to-rails-8-1).

## Third-party compatibility and warning classification

Baseline lockfile constraints admit Rails 8.1 for Devise 5.0.4, route_translator 16.0.1, pg_search 2.3.6, Sprockets Rails 3.4.2, RSpec Rails 8.0.4, Simple Form 5.3.0, Turbo Rails 1.5.0, importmap-rails 1.2.3, Stimulus Rails 1.3.0, and tailwindcss-rails 2.3.0. Constraint compatibility is not proof of runtime compatibility. These selected gems were inspected for the listed removed APIs; the search did not originally cover Carmen. Route translation hooks into router internals, `pg_search` builds SQL and accesses connections, and form/asset engines integrate with Rails rendering/initialization, so boot, request/search/form, asset, and browser checks remain necessary. Upgrade these gems only for a demonstrated failure.

### Demonstrated Carmen incompatibility and release research

Context7 resolution was attempted for `Carmen` and `carmen-ruby/carmen`; neither returned a relevant library, so official package metadata and upstream source were inspected. Fresh RubyGems versions/metadata APIs confirm 1.1.3, released 2019-07-02, is the latest non-yanked release; there is no newer compatible release or prerelease. Its Ruby requirement is unconstrained (`>= 0`), with only `activesupport >= 3.0.0` as a runtime dependency. There is therefore no lowest release fixing `mb_chars` to select. [Official releases](https://rubygems.org/gems/carmen/versions), [current versions API](https://rubygems.org/api/v1/versions/carmen.json), [package metadata API](https://rubygems.org/api/v1/gems/carmen.json).

Upstream `master` still contains the identical `name.mb_chars.downcase.unicode_normalize(:nfkc)` implementation. Its unreleased changelog contains country/subregion data updates and no normalization fix. Switching to a Git dependency would introduce unrelated geographic data changes without fixing the incompatibility, so retaining Carmen 1.1.3 is justified. [Upstream lookup](https://github.com/carmen-ruby/carmen/blob/master/lib/carmen/querying.rb), [upstream changelog](https://github.com/carmen-ruby/carmen/blob/master/CHANGELOG.md), [upstream gemspec](https://github.com/carmen-ruby/carmen/blob/master/carmen.gemspec).

For UTF-8 application strings, native `String#downcase.unicode_normalize(:nfkc)` preserves Carmen's intended matching: Rails 8.0 `Multibyte::Chars` proxies those same String methods. A localized remedy must retain case-insensitive matching, NFKC normalization, translated country names, existing geographic data, and `nil` when no country matches. Case-sensitive `Country.named(..., case: true)` would bypass the warning while changing behavior and is unsuitable. For non-UTF-8 inputs, the old wrapper additionally forced UTF-8 encoding; that distinction should be considered if such inputs are supported. [Baseline proxy implementation](https://github.com/rails/rails/blob/v8.0.5.1/activesupport/lib/active_support/multibyte/chars.rb#L55).

Record observed warnings and their emitting file in the upgrade record: A for application compatibility, B for third-party code, C for deferred defaults, D for pre-existing/environmental warnings. Bundler's observed ambiguous installed `stringio` specifications warning is D: installed runtime gem metadata, not a Rails application deprecation. Test configuration already raises Rails deprecations, development logs them, and production intentionally suppresses them; validation must capture test/development output. Source searches are not a substitute for running the suite, and this audit does not claim an unexercised path is warning-free.
